# Proposal: lottery-ceremony-animation

## Background
当前抽奖页已具备「贝壳 / 抽奖券」资产展示、兑换、抽一次、奖池列表与券包入口；抽奖由云函数 `lottery_draw` 在服务端执行并返回券实例。

但体验偏“功能按钮 + 列表”，缺少温柔的「微仪式感」：点击后立刻弹 modal，缺少“打开礼物”的过程。

## Goals
- 为抽奖增加 **800ms ~ 1200ms** 的“微动效仪式”：
  - 点击「打开一份小礼物」后页面轻微模糊/变暗
  - 中央浮出礼物卡片（淡入 + 上浮 + scale）
  - 展示结果文案
  - 用户点击「收进礼物盒」完成确认
- 抽奖随机 **在服务端执行**（不在 UI 层算随机）。
- 奖池展示不包含概率高亮/博彩暗示；不做转盘/老虎机。

## Non-goals
- 不做转盘动画、老虎机滚动、闪烁爆炸、音效轰炸。
- 不展示或强调“概率/爆率”。（页面不出现百分比）
- 不引入新依赖（包含动效库、第三方组件库）。

## Risks & Mitigations
- 风险：被误解为博彩
  - 缓解：不显示概率、不使用转盘老虎机、不做刺激性动效；文案使用“礼物/收纳/橱窗/礼物盒”。
- 风险：重复点击导致重复扣券/重复发券
  - 缓解：前端 drawing 状态锁；服务端继续保持一次调用消耗 1 张券，并在 ledger 侧可追溯。

## Rollback
- 前端：可通过回滚本 change 将抽奖页恢复为原先“直接 showModal”的结果展示。
- 后端：保留 `lottery_draw` 原接口返回结构，动画仅为展示层；即使 UI 回滚也不影响数据。
