# Change: Murmur Composer V2（碎碎念发布页）

## Background
当前发布页（`/pages/entry/publish`）呈现为“工具化表单”：
- 标题非日期语境
- 显眼的按钮区（发布/取消）
- 显眼的计数（0/500）
- 工具计数“图片(0/9)”

与产品定位（轻量、干净、随手碎碎念）不一致。

## Why
降低任务感与工具感，让发布页更像翻开的一页纸/便签，强化“情绪表达”而不是“提交表单”。

## What Changes
- 仅做 UI/交互文案与布局调整（不改后端接口与数据结构）
- 顶部标题改为当日日期（如“2月16日”）
- 图片入口从“图片(0/9)+添加”改为“+ 添加照片”，不展示工具计数
- 删除“取消”按钮，仅保留一个主动作按钮
- 主按钮文案改为“说完了”，且仅在（trim(text)非空 或 images.length>0）时可点击
- 字数计数默认隐藏，仅在剩余<=50 时显示

## Non-Goals
- 不新增贴纸/标签/定位/音乐等新功能
- 不改发布业务流程（仍走现有上传→entry_create→navigateBack）
- 不改图片上限逻辑（保持当前实现为 9 张）
- 不引入新依赖/组件库
- 不改后端接口/数据结构

## Risks
- UI 改动可能影响可用性（按钮不可点击状态/键盘遮挡）。

## Rollback
- 单次提交可回滚：仅修改 `miniprogram/pages/entry/publish.(wxml|wxss|js)`。

## Acceptance Criteria
1) 页面标题为日期（如 2月16日），不再出现“留下些什么/写日记/发布”标题语境
2) 页面不再显示“取消”按钮
3) 主按钮文案为“说完了”，且仅在有内容/有图时可点
4) 图片入口显示为“+ 添加照片”，不显示“图片(0/9)”
5) 字数计数默认隐藏，仅在剩余<=50时显示
6) 发布成功：返回并刷新上一页数据（与现状一致）
7) 无 UI 抖动、无遮挡、无报错
