# Change: Naming System V1（贝忆命名系统重构）

## Background
当前小程序内多处文案呈现出“工具/表单/任务化”语气，且首页/记录页/情绪卡片等核心触点的叙事不一致，和产品定位（温柔陪伴、想念收纳）不匹配。

## Why
统一首页与记录页的命名系统与语气，让产品像两个人的“想念收纳处”：记录的是“因为你而发生的那一刻”。主入口命名以情绪驱动而非功能驱动，减少解释、保留留白。

## What Changes
- 仅进行命名/文案/信息架构文字层面的重构
- 引入统一的 strings 常量层（Key 管理），禁止页面散落硬编码
- 提供统一日期格式化 util（"2月17日"）与昵称 fallback 规则
- 覆盖页面（本仓库实际存在的）：
  - 首页 `page-home`
  - 记录/发布页 `page-entry-publish`
  - 首页情绪卡片（home 页面内）
  - 日详情页 `page-day-detail`（评论与按钮文案）
  - 设置页 `page-settings`
  - 关系创建/加入页：`page-relationship-create` / `page-relationship-join`

> 说明：需求中提到“约会模块”，但本仓库当前未发现对应 **小程序页面**（仅存在 `cloudfunctions/date_*`）；因此本 change 不改约会页面 UI，仅在 spec 中记录该限制，后续在约会页面落地时再统一命名。

## Non-Goals
- 不改后端接口/数据结构
- 不新增功能（不做记录类型选择/标签/贴纸/通知等）
- 不引入新依赖
- 不做视觉大改（仅允许为放置副标题/来源提示做轻微布局调整）

## Risks
- 文案替换可能影响用户理解（特别是“发布/取消”等习惯词被替换）。

## Rollback
- 保留 strings key 的同时可快速切回旧文案映射；单次提交可回滚到 change 之前。

## Acceptance Criteria
1) 首页：保留“和 {TaNickname} 的第 {DayCount} 天”
2) 首页情绪卡片：显示来源提示
   - `来自 {TaNickname} 的碎碎念` 或 `我写给 {TaNickname} 的碎碎念`
3) FAB 入口加一个气泡暗示（轻量、不工具化），文案为“想你的碎碎念”
4) 发布页：
   - 标题为日期（2月17日）
   - 副标题为“{MyNickname} 的碎碎念收纳处”
   - 提示语/placeholder/按钮等符合温柔陪伴语气：记录下这一刻的想法、心情、发生的小事，把这一刻收好，送给 {TaNickname}；主按钮为“收好”
5) 设置页/日详情页关键 CTA 文案去工具化并统一
6) 全部文案来自统一 strings/key，不散落硬编码
7) 不改后端接口/数据结构；无报错
