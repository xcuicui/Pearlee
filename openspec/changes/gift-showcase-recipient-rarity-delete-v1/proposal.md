# Proposal: gift-showcase-recipient-rarity-delete-v1

## 背景
当前“小礼物橱窗”是静态奖池（服务端常量 + 前端常量），缺少“为对方准备礼物”的参与感：
- 无法明确每份礼物是“送给谁”
- 抽取时无法只抽到“对方给我准备的礼物”
- 礼物稀有度无法配置
- 无法将礼物从橱窗中移出（删除/下架）

## 目标
- 礼物支持 recipient（送给谁）。
- 抽礼物时仅从“送给我”的礼物池抽（recipient=currentUser）。
- 上传礼物时支持稀有度（常见/偶尔/稀有），权重由后端映射计算，UI 不展示概率。
- 支持“移出橱窗”（软删除），且删除后不影响历史已抽到的礼物展示。
- 全流程保持温柔陪伴风格，不博彩、不展示概率百分比。

## 风险
- 礼物池为空：需要明确空态提示与按钮禁用。
- 历史数据兼容：已有 pocket 礼物（当前 coupons）必须可继续展示。

## 回滚
- 前端：隐藏/关闭 AddGift/橱窗分段与删除入口，回退为静态橱窗。
- 后端：保留旧抽取逻辑分支（常量奖池）作为回退路径；或回滚 `lottery_draw` 对新礼物池的查询逻辑。
